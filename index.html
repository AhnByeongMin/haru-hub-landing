CRM 분석 자동화 2.0 — 화면을 누르던 자동화에서, 요청을 직접 주고받는 작업 엔진으로

일반 웹 자동화가 통하지 않는 사내 CRM(넥사크로)을 사람 대신 눌러 주던 1.0에서 시작했습니다. 2.0은 화면이 보내는 조회 요청의 틀을 한 번 잡아 두고 날짜·쪽만 바꿔 응답을 직접 받고, 계산까지 서버가 끝내는 여러 사람이 함께 쓰는 웹 작업 엔진입니다. 11월 2일, 메뉴마다 1.0 결과와 칸 단위로 대조한 뒤 1.0을 정리하고 2.0만 운영합니다. 새 계산은 운영 복사본에서 돌려 다른 칸이 0개일 때만 넣습니다.

대표 사례 · 연계 터치 확인 (사용 기록 10/22~11/6)

날짜 하루치마다 반나절 걸리던 연계 실적 확인 → 한 달치 4분, 사람은 남은 1%만 확인.

하루치마다 반나절이 걸려 하루만 밀려도 다음 날 일이 두 배가 됐고, 쌓일수록 따라잡기 어려웠습니다. 지금은 한 달치를 하루에 몰아서 해도 됩니다(실행 약 4분 + 남은 1% 확인). 밀리면 쌓이던 확인 업무가 몰아서 해도 되는 일이 됐습니다.

  • 이전 전체 계약에서 우리 것이 아닌 계약과 외부 채널 상담사 건을 거르고, 남은 계약을 하나씩 열어 우리 팀이 먼저 터치했는지 확인했습니다. 영업일 하루치마다 한 명이 반나절 이상.
  • 2.0 거르기부터 터치 확인(고객번호·연락처 대조)까지 자동. 한 달치 1회 실행 약 4분(최근 62회 중앙값 4분 16초).
  • 11/6 실측 약 26영업일치 원본 약 2.4만 건 → 자동 거르기 뒤 약 7천 건 → 자동 확정 53건, 사람이 볼 '확인 필요' 236건(원본의 약 1%). 사람 기준 13인일 이상이 '실행 4분 + 남은 1% 확인'으로 줄었습니다.

  • 사은품 누락 자동 검수 · 실적 캡처 4종 한 번에
  • 장애 대비 계산기 엑셀 — 전산이 멈춰도 내보내기 파일을 붙여 넣으면 수식만으로 같은 표(웹과 60개 표 대조, 같음)

상담 CRM 2.0 — 운영 중인 시스템을 멈추지 않고 다시 짓다

직접 만들어 운영하던 상담 CRM(1.x)을 여러 사람이 동시에 써도 데이터가 틀어지지 않는 구조로 처음부터 다시 설계했습니다. 운영을 멈추지 않은 채 옮긴 뒤 1.x를 껐습니다. 데이터와 동작은 그대로, 구조와 화면은 새로. 옮긴 뒤에도 상담 도구와 관리자 녹취 편집기를 붙이며 키우고 있습니다.

녹취관리자 녹취 편집기 — 옛 전화 녹음 형식도 브라우저에서 바로 열고, 자르고, 줄입니다. 편집하는 동안 녹취 파일은 그 PC 밖으로 나가지 않고, 받아쓰기를 요청할 때만 집 안 GPU로 한 번 갔다가 지워집니다.

반응메뉴를 누르면 바로 화면을 보여 주고, 쉬는 틈에 다음 화면을 미리 받아 둡니다. 같은 탭 안에서만 메모리에 담아 두어 다른 로그인과 섞이지 않습니다.

  • 02 · 성능

    네트워크 탓만이 아니라, 보내는 방식의 문제

    화면 하나가 서버 호출 14건을 동시에 보내고, 응답은 압축·분할 없이 XML 통째로 옵니다. 두 가지가 겹쳐 100Mbps 공용 회선을 채웁니다 — 병렬 6~10개에서 병목, 30MB 응답 약 23초. 회선 이론값(약 2.4초)보다 훨씬 길어 회선과 서버 처리 양쪽을 원인으로 봤습니다. gzip 압축·SSV 전환·분할 전송을 제안했고, 공식 화면에서 재현한 자료와 함께 외부 담당에게 전달했습니다.

  • 03 · 요구

    코드 대신 지표를 요구하다

    지연 건은 "지금은 정상"으로 건별 종결됐고, 코드 검증은 보안을 이유로 막혔습니다. 코드 대신 슬로우 쿼리·실행 계획·배치 스케줄·응답시간 제출을 요구하는 공식 개선 요청 체계를 만들었습니다. 건별 대응이 팀 명의의 품질 개선 요구로 바뀌었습니다.

결함을 찾는 데서 끝내지 않고, 같은 전산 위에서 부하를 일으키지 않는 자동화를 직접 만들어 운영합니다.
